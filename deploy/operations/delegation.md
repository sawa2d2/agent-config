# Delegation procedures

Read before launching, coordinating, or reporting delegated branch work.

- Delegate command: `agent-delegate` (Claude Code), `bob-delegate` (Bob Shell), or `codex-delegate` (Codex), run as `<cmd> <new-branch> "<task and context>"`. It creates the branch in a new worktree and starts the agent, which does the work, in a new tmux window without moving focus; never create that branch here (no `git checkout -b`, `git switch -c`, or `git worktree add`).
- Codex: the originating agent remains the coordinator in its original checkout, including on the default branch. For user-requested orchestration, use `codex-delegate --list` and `--status <id>` on demand, review explicit worker summaries/checks/commits, and verify Git results before accepting completion. Management does not authorize editing worker files from the parent or committing to the default branch. Workers implement in their assigned worktrees. Do not manage other agent types, inject follow-up input, or merge automatically. Report blocked shared-state writes; never use a local fallback.
- Preserve existing user authorization in delegated tasks. Within that authorization, by default explicitly delegate commit and push of completed, verified assigned development-branch changes (the Codex launch prompt already does so). Preserve actual user restrictions; do not invent read-only or uncommitted-only limits. Test subagents remain read-only, and default-branch, merge, force-push and security-review requirements still apply. Report a denied operation with its specific scope and reason; never turn an individual denial into a blanket restriction on later tasks.
- Codex execution permissions are session-specific. The delegate launches a fresh worker with `--sandbox danger-full-access --ask-for-approval on-request`; the wrapper preserves those explicit flags. This does not change an already-running coordinator's workspace-write/automatic-review policy. Launch/report writes to the repository's shared `.git` metadata may therefore need the coordinator's normal tool approval path. Existing commit/push authorization removes repeated conversational confirmation, not runtime security checks. Inspect the actual worker launch and active permissions before diagnosing propagation; report automatic-review denials with the operation and reason, never bypass them or infer a ban on future authorized tasks.
- Install global launchers and operational references only from the persistent original agent-config checkout. A deleted development worktree can leave installed links dangling. Do not change HOME to repair them without authorization; report the broken paths and required reinstall. Worker reports use the resolved repository launcher path so a missing PATH link does not prevent reporting while that source checkout remains available.
- Delegation: input sent is not verified startup. Require the delegate's bounded startup check to succeed; Codex waits for the worker's concrete starting report. On timeout, delivery failure or inaccessible tmux, report the uncertainty and inspect retained task/pane/worktree state before retrying. Never blindly resend or launch a duplicate. An access denial does not prove a pane is missing. Workers must report their actual first action, replacing example summary/check text, and explain any blocked report write.
- Always delegate to the originating agent (Claude to Claude, Bob to Bob, Codex to Codex), even if another agent's command is available.
- For an explicitly named target repository, use `codex-delegate --repo "<path>"` for launches and repository-scoped `--list`/`--status` commands; place `--repo` before the branch. Otherwise cwd remains the default. With `--report`, select the assigned worker worktree, not the original checkout. Claude's command is `agent-delegate`, not `claude-delegate`; it and `bob-delegate` do not support `--repo`, so run them from the target checkout.
- For routine, low-reasoning Claude work (merge waits, branch cleanup, mechanical edits), pass `-m sonnet` to `agent-delegate`; otherwise keep the default model.
- The Codex parent must explicitly select `-m gpt-6.1-sol` for ordinary tasks or `-m gpt-6-astra` for heavy tasks when running `codex-delegate`. Judge complexity, uncertainty, and impact rather than changed line count.
